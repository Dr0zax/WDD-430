## 1. Problem Statement

Hearing isolated chords is not enough to evaluate a progression. Users need to play the chords in workspace order with simple timing so they can hear the musical idea they assembled.

## 2. Goals

- Play progression chords in order using the chord playback service.
- Use a fixed MVP duration or the workspace’s basic tempo and duration fields.
- Provide play and stop controls and highlight the current chord.

## 3. Non-Goals

- Pause/resume, looping, metronome, recording, export, or timeline editing.
- Complex arrangement timing or synchronization with external devices.

## 4. Personas & User Stories

- **As a songwriter**, I want to hear my progression in order so I can evaluate its flow.
- **As a learner**, I want the currently playing chord highlighted so I can follow along.

## 5. Functional Requirements

- **FR-1.** Play MUST visit workspace chords in their displayed order.
- **FR-2.** Each chord MUST play for the configured duration or the documented MVP default.
- **FR-3.** The current chord MUST have a visible and accessible playing state.
- **FR-4.** Stop MUST cancel future playback and release active voices.
- **FR-5.** Empty or invalid progressions MUST not start playback.

## 6. Non-Functional Requirements

- **Performance** — chord transitions SHOULD remain within 50 ms of their scheduled time.
- **Reliability** — cleanup MUST occur on stop, navigation, and component unmount.
- **Accessibility** — playback position MUST be communicated without color alone.

## 7. Acceptance Criteria

- **AC-1.** Given a four-chord progression, when Play is activated, then chords sound in displayed order.
- **AC-2.** Given active playback, when the second chord begins, then the second workspace row is marked current.
- **AC-3.** Given active playback, when Stop is activated, then no later chord sounds.
- **AC-4.** Given an empty workspace, when the controls render, then Play is disabled and explains how to add chords.
- **AC-5.** Given a malformed progression, when Play is activated, then validation prevents playback and preserves the draft.

## 8. Data Model

Consume the serializable progression object from F2.4 and transient scheduler state containing current index and playback status.

## 9. API Surface

No server route. Consume the playback service from F2.6.

## 10. UI / UX

Add progression Play and Stop controls, current-step styling, status text, and disabled/error states to the progression builder.

## 15. Rollout Plan

- Feature flag: `progression-audio-playback` default on.
- Release with a fixed four-beat default if configurable timing is not ready.
- Rollback by hiding progression playback while retaining chord playback.

## 16. Test Plan

- **Unit** — duration conversion, ordering, cancellation, and invalid drafts.
- **Integration** — workspace progression mapped to scheduled chord events.
- **End-to-end** — play and stop a four-chord progression.
- **Accessibility** — controls, current-step announcement, and focus behavior.
- **Manual exploratory** — stop during each chord, navigate away, and restart.
