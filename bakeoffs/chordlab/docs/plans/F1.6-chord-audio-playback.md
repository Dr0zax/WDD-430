## 1. Problem Statement

Users need to hear the notes they selected before deciding whether a chord belongs in a progression. The current piano interaction has no audio output, so it only provides visual exploration.

## 2. Goals

- Play selected piano notes together as a chord.
- Provide play and stop controls with clear status feedback.
- Handle browser audio initialization and unsupported-device errors.
- Ensure repeated playback does not leave active sounds behind.

## 3. Non-Goals

- Studio-quality instruments, recording, effects, export, or external MIDI output.
- Sequencing multiple chords; that is covered by F2.7.

## 4. Personas & User Stories

- **As a musician**, I want to hear a selected chord so I can judge its sound.
- **As a learner**, I want playback to match the notes shown on the piano.

## 5. Functional Requirements

- **FR-1.** Play MUST trigger one voice for each selected note.
- **FR-2.** Stop MUST release all active voices and reset playback status.
- **FR-3.** Play MUST be disabled when no notes are selected.
- **FR-4.** Audio initialization failures MUST display an actionable error.
- **FR-5.** Starting a new playback MUST stop or replace the previous playback cleanly.

## 6. Non-Functional Requirements

- **Performance** — playback SHOULD start within 150 ms of a user gesture.
- **Reliability** — unmounting the component MUST release active voices.
- **Accessibility** — playback status MUST be announced without relying on color alone.

## 7. Acceptance Criteria

- **AC-1.** Given C, E, and G selected, when Play is activated, then all three notes sound together.
- **AC-2.** Given active playback, when Stop is activated, then all active voices release and the status returns to idle.
- **AC-3.** Given no selected notes, when the controls render, then Play is disabled with an explanation.
- **AC-4.** Given an audio initialization failure, when Play is activated, then the UI shows a retry or recovery action without crashing.
- **AC-5.** Given active playback, when Play is activated again, then the prior playback is cleaned up before the new playback starts.

## 8. Data Model

Use transient `PlaybackState` with status, active note IDs, and error message. No persistence is required.

## 9. API Surface

No server route. Add a client playback service consumed by the piano interface and progression player.

## 10. UI / UX

Add Play and Stop controls beside the selected-note summary. Include disabled, loading/initializing, playing, stopped, and error states.

## 15. Rollout Plan

- Feature flag: `chord-audio-playback` default on where Web Audio is supported.
- Pilot with a simple bundled instrument or oscillator.
- Rollback by hiding audio controls while retaining piano input.

## 16. Test Plan

- **Unit** — note scheduling, stop cleanup, empty input, and error states.
- **Integration** — selected notes reach the playback service in order.
- **End-to-end** — select notes, play, stop, and play again.
- **Accessibility** — button labels, focus, status announcements, and disabled state.
- **Manual exploratory** — Chrome, Edge, mobile browser gesture behavior, and rapid Play/Stop.

## 17. Documentation & Training

Explain that the first Play action may initialize the browser’s audio context.
