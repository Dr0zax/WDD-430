## 1. Problem Statement

Seeing compatible chords is useful, but the project’s core outcome is building a progression idea. Users need to add, remove, and reorder selected chords in a simple workspace.

## 2. Goals

- Add chords from the explorer to an ordered progression.
- Remove and reorder chords.
- Show positions and a basic duration for each chord.
- Validate empty and overlong progressions without losing the current draft.

## 3. Non-Goals

- Audio playback, saving, renaming, sharing, MIDI, guitar diagrams, or AI generation.

## 4. Personas & User Stories

- **As a songwriter**, I want to arrange compatible chords so I can sketch a progression.
- **As a learner**, I want the progression order and chord names visible so I can understand the result.

## 5. Functional Requirements

- **FR-1.** The workspace MUST maintain an ordered list of selected chords.
- **FR-2.** Users MUST be able to add, remove, and move chords up or down.
- **FR-3.** The workspace MUST show chord symbol, position, and duration beats.
- **FR-4.** The workspace MUST show an empty state before the first chord is added.
- **FR-5.** The workspace MUST reject invalid entries and preserve the valid draft.
- **FR-6.** The workspace MUST expose a serializable progression object for future persistence.

## 6. Non-Functional Requirements

- **Performance** — add, remove, and reorder feedback SHOULD appear within 100 ms.
- **Accessibility** — all editing actions MUST be keyboard accessible.
- **Responsive** — the workspace MUST stack cleanly on mobile.

## 7. Acceptance Criteria

- **AC-1.** Given a selected chord, when Add is activated, then it appears at the end of the progression.
- **AC-2.** Given three chords, when the second is moved up, then the displayed order and positions update.
- **AC-3.** Given a progression, when one entry is removed, then the remaining positions are renumbered.
- **AC-4.** Given no chords, when the workspace renders, then it explains how to add the first chord.
- **AC-5.** Given an invalid operation, when it is attempted, then a specific error appears and the valid draft remains intact.

## 8. Data Model

Use the specification’s Progression shape in client state: title, key, scale, tempo, timeSignature, ordered chords, and timestamps as optional local fields.

## 9. API Surface

No persistence route is required for this MVP. Expose a typed client callback or serialized object for later API work.

## 10. UI / UX

Add the workspace beside or below the explorer with chord rows, add/remove/move controls, empty state, validation state, and a compact progression summary.
