## 1. Problem Statement

The project requires user accounts so the application has a real user workflow and can safely add user-owned data later. The current app has no sign-up, login, or logout behavior.

## 2. Goals

- Support sign up, log in, log out, and current-session checks.
- Validate email, display name, and password inputs.
- Keep credentials secure and expose only safe error messages.

## 3. Non-Goals

- Social login, email verification, password reset, roles, or account administration.

## 4. Personas & User Stories

- **As a new user**, I want to sign up so I can use ChordLab as my own account.
- **As a returning user**, I want to log in and log out from the main interface.

## 5. Functional Requirements

- **FR-1.** `POST /api/auth/register` MUST create a user from validated email, password, and display name.
- **FR-2.** `POST /api/auth/login` MUST establish a session for valid credentials.
- **FR-3.** `POST /api/auth/logout` MUST invalidate the current session.
- **FR-4.** `GET /api/auth/me` MUST return the current user or 401.
- **FR-5.** Passwords MUST be hashed and MUST NOT appear in logs or responses.

## 6. Non-Functional Requirements

- **Security** — use secure, httpOnly session cookies and owner-neutral authentication errors.
- **Accessibility** — forms MUST have labels, focus handling, and associated errors.

## 7. Acceptance Criteria

- **AC-1.** Given valid sign-up data, when the form is submitted, then an account is created and the user receives an authenticated state.
- **AC-2.** Given invalid credentials, when login is submitted, then the form shows a safe error without revealing which field was incorrect.
- **AC-3.** Given an authenticated user, when logout is activated, then `/api/auth/me` returns 401.
- **AC-4.** Given invalid or missing form fields, when submit is attempted, then validation prevents the request and explains the correction.

## 8. Data Model
